# StreetSmart Mobile Strategy

StreetSmart ships as **both** a Progressive Web App (PWA) and a native-packaged app (via Capacitor).

- **PWA** — install instantly from the browser on iOS / Android. No app-store friction.
  Works offline (Workbox service worker caches the app shell and API responses).
- **Capacitor** — wraps the same React web build in a native shell so the app can be
  listed on the Apple App Store and Google Play, and can access native APIs
  (push notifications, biometrics, secure storage, haptics).

### Add to Home Screen — user instructions

**iOS Safari:**
1. Open the live URL in Safari.
2. Tap the Share icon → **Add to Home Screen**.
3. Accept the suggested name → **Add**.

**Android Chrome:**
1. Open the live URL in Chrome.
2. Tap the three-dot menu → **Add to Home Screen**, or wait for the browser install prompt.

### Replacing placeholder icons

The placeholder icons in `public/icons/` are generated programmatically with the StreetSmart
colour palette. Replace them with high-quality artwork before the first production release:

- `icon-192.png` — 192 × 192 px, opaque background (so the `maskable` purpose renders correctly on Android)
- `icon-512.png` — 512 × 512 px, same rules

Tools: Figma export, RealFaviconGenerator, or any image editor.

## 2. Capacitor — native iOS / Android packaging

Capacitor wraps the Vite production build (`dist/`) in a native WebView and adds access to
device APIs. The config lives in `capacitor.config.json` at the repo root.

### Prerequisites

- Node.js ≥ 18 and the project's npm dependencies installed.
- **iOS**: macOS, Xcode ≥ 15, CocoaPods installed (`gem install cocoapods`).
- **Android**: Android Studio, JDK 21, Android SDK (API 33+).

### First-time native project setup

```bash
# 1. Build the web app
npm run build

# 2. Add platforms (run once)
npx cap add android
npx cap add ios

# 3. Sync web assets into the native projects
npm run cap:sync
```

### Day-to-day development

```bash
# After any web code change:
npm run build && npm run cap:sync

# Open in Android Studio:
npm run cap:android

# Open in Xcode:
npm run cap:ios
```

### App metadata (set before first store submission)

| Setting | Android path | iOS path |
|---|---|---|
| App ID | `android/app/build.gradle` → `applicationId` | `ios/App/App.xcodeproj` → Bundle Identifier |
| Version | `android/app/build.gradle` → `versionName`/`versionCode` | Xcode → Version / Build |
| Icons | `android/app/src/main/res/mipmap-*` | `ios/App/App/Assets.xcassets/AppIcon.appiconset` |
| Splash | Install `@capacitor/splash-screen` and configure in `capacitor.config.json` |

### Auth token handling in native lifecycle

The React app stores the JWT in `localStorage` via `AppState.jsx`.  Capacitor persists
`localStorage` across app restarts in the native WebView, so no extra bridge code is needed
for basic auth persistence.

For heightened security (biometric unlock of the token), install and configure
`@capacitor/biometrics` and move token storage from `localStorage` to
`@capacitor/preferences` (which maps to the native secure storage on each platform).

### Deep links

To handle deep links (e.g. from push notification taps):

1. Register URL schemes in `capacitor.config.json`:
   ```json
   { "plugins": { "App": { "launchUrl": "streetsmart://" } } }
   ```
2. Add `appUrlOpen` listener in the React app:
   ```js
   import { App } from '@capacitor/app'
   App.addListener('appUrlOpen', ({ url }) => { /* navigate via react-router */ })
   ```
3. Configure universal links (iOS) / App Links (Android) in the hosting platform's
   `apple-app-site-association` / `assetlinks.json` files.

## 3. Push notifications

1. Install the plugin: `npm install @capacitor/push-notifications`
2. Request permission on first launch (after a meaningful interaction, not immediately).
3. Send the device token to the backend (`POST /api/devices/register`) so the backend can
   fan out alerts via APNs (iOS) or FCM (Android).
4. The backend's job-queue (`backend/src/queue.mjs`) is the right place to enqueue push
   delivery jobs — mirror the existing briefing-delivery email pattern.

---

## 4. Offline and connectivity hardening

- **Service worker (Workbox)** — already configured in `vite.config.js`.  The app shell and
  static assets are pre-cached; API responses fall back to the cached copy when offline.
- **Offline indicator** — `OfflineIndicator` component mounts at app root and shows a
  banner when `navigator.onLine` is false.
- **Retry logic** — the API client (`src/api/client.js`) currently propagates errors
  immediately. For resilience on poor mobile connections, wrap `request()` with exponential
  backoff using `@capacitor/network` to detect connectivity before retrying.

## 5. Performance budgets

Target thresholds for low-end devices (Moto G-class, iPhone SE):

| Metric | Target |
|---|---|
| First Contentful Paint | < 1.8 s (on fast 3G) |
| Time to Interactive | < 3.5 s |
| JS bundle (gzipped) | < 250 kB |
| Lighthouse PWA score | ≥ 90 |

Run `npx lighthouse <url> --view` in CI to track these.

## 6. Crash and analytics instrumentation

Recommended minimal stack (no third-party tracking SDKs required):

- **Error reporting** — wrap `ReactDOM.createRoot` render in a React Error Boundary and
  POST uncaught errors to `POST /api/errors` (add this endpoint to the backend).
- **Performance** — use the browser PerformanceObserver / Web Vitals API to collect LCP,
  FID, CLS and send to a logging endpoint.
- **Native crashes** — install `@capacitor/firebase-crashlytics` (requires Firebase project)
  or use Sentry's Capacitor SDK.

## 7. Mobile CI pipelines

### Android build (GitHub Actions)

Add `.github/workflows/mobile-android.yml` to build and publish a signed APK / AAB to Play
Internal Testing on every push to `main`.

Required secrets:
- `ANDROID_KEYSTORE_BASE64` — base64-encoded JKS keystore file
- `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`, `ANDROID_STORE_PASSWORD`
- `GOOGLE_PLAY_SERVICE_ACCOUNT_JSON` — service-account JSON for the Play API

### iOS build (GitHub Actions with macOS runner)

Add `.github/workflows/mobile-ios.yml` to build and submit to TestFlight on every push to `main`.

Required secrets:
- `APPLE_CERTIFICATE_BASE64`, `APPLE_CERTIFICATE_PASSWORD`
- `APPLE_PROVISIONING_PROFILE_BASE64`
- `APPLE_API_KEY`, `APPLE_API_ISSUER_ID`, `APPLE_API_KEY_ID`
